#Agent Design Skills — Operating Instructions

You are expected to use this skill set whenever you create, modify, review, or redesign a user interface.

1. Mandatory entry point

At the start of every applicable task, read "SKILL.md" completely. It identifies the skills that must be loaded for interface work.

For any UI task, read all of the following files completely:

1. "product-native-ui.md"
2. "ui-composition.md"
3. "color-intelligence.md"
4. "skill-fidelity.md"

Do not select only the files that appear relevant. These requirements are complementary and must be applied together.

2. How to execute

1. Inspect the existing product, its purpose, users, workflows, implementation and established design system.
2. Read the entry-point file and every required skill from beginning to end before implementation.
3. Identify the applicable requirements, prohibitions, conditions and verification criteria.
4. Plan the work around the actual product and user workflow. Do not impose a generic visual style or redesign unrelated areas.
5. Apply the requirements throughout implementation. Do not drift back to default component styling or generic AI-generated patterns.
6. Review the actual rendered interface at relevant screen sizes and interaction states.
7. Compare the finished work against the original skill files and correct deviations before completion.
8. Report limitations honestly. Never claim to have read, implemented or verified something you have not.

3. Instruction compliance

These skills are mandatory operating instructions, not optional suggestions.

- Never skim or partially read a required skill.
- Never silently ignore a requirement.
- Never replace explicit instructions with personal defaults.
- Never weaken mandatory requirements into preferences.
- If a file cannot be accessed or fully read, stop the affected work and report the limitation.
- If requirements conflict, resolve the conflict according to instruction priority and explain material conflicts.
- Keep the requirements active throughout planning, implementation, testing and review.

4. Quality expectations

The objective is to produce interfaces that feel like mature, commercially credible software products.

Prioritize:

- Product-native experiences over presentation-style interfaces.
- Professional layout composition and appropriate component proportions.
- Intentional alignment, spacing and visual hierarchy.
- Deliberate color selection and coherent palettes.
- Purposeful use of surfaces and contrast instead of unnecessary borders.
- Concise, natural interface copy.
- Consistent interaction states and accessible controls.
- Functional clarity over decorative complexity.

Do not mistake visual complexity for quality, minimalism for professionalism, or a collection of styled components for a well-designed product.

5. Completion standard

Before declaring UI work complete, verify the actual implementation against every applicable skill.

Correct visible deviations. Identify anything that remains incomplete and explain why.

Operating principle: Read completely. Understand accurately. Execute faithfully. Verify independently.
