# Agent Engineering Skills

A set of independent, mandatory skills for building and evaluating software products.

## Included skills

1. `clean-code` — readable, modular, reusable, secure and efficient implementation; naming, responsibilities, errors, concurrency, performance, dependencies and restrained comments.
2. `software-architecture` — product discovery, system boundaries, architecture selection, data ownership, APIs, security, reliability, infrastructure and architecture decisions.
3. `code-review-testing` — systematic code review, severe defect hunting, security and race-condition checks, test strategy, regression prevention, full-project audits and release gates.
4. `product-critic-benchmarking` — mandatory research and intensive inspection of 15 relevant websites, evidence logs, benchmark synthesis, weighted scoring and iterative repair/retesting.

## Recommended loading order

For a new product or major feature:

1. Read `software-architecture` before making consequential system decisions.
2. Read `clean-code` before writing or modifying code.
3. Read `product-critic-benchmarking` before designing or evaluating a user-facing website or digital product.
4. Read `code-review-testing` before reviewing, testing or declaring work complete.

These files are not mutually exclusive. Apply all relevant skills throughout the task, not just once at the beginning.

For visual work, also load the separate `product design taste` skill. This bundle does not replace it.

## Mandatory agent operating rule

The agent must locate and read the complete contents of every applicable skill before acting. It must not rely on filenames, summaries, metadata, excerpts or remembered versions. If the full contents cannot be accessed, it must disclose that limitation and must not claim full compliance.

The agent must retain the requirements while working and verify the deliverable against the applicable quality gates. A checklist is not evidence unless the corresponding work was actually performed.

## Important limits

- The 15-site benchmark requires real browser or web access. The agent must not invent research when that access is unavailable.
- Performance, security, accessibility and test claims require actual checks. Do not fabricate scores or successful results.
- The benchmark is a quality and learning process, not permission to copy another company's code, protected assets, copywriting or distinctive visual identity.
- A `PASS` verdict is not permitted where a mandatory quality gate is unverified or failed.
