# Product Design & Instruction Fidelity — Skill Index

These skills define the required design quality and execution discipline for interface work.

## Required skills

For any task that creates, edits, reviews or redesigns an interface, load all four files:

1. `product-native-ui.md`
2. `ui-composition.md`
3. `color-intelligence.md`
4. `skill-fidelity.md`

Do not load only the file whose title seems most relevant. The requirements work together.

## Priority and interpretation

- Follow higher-priority system and developer instructions first.
- Within those boundaries, treat the requirements in these files as mandatory.
- Do not weaken explicit requirements into preferences.
- Do not invent exceptions or silently omit requirements.
- If requirements conflict with the product brief, existing design system, accessibility, platform conventions or technical constraints, identify the conflict and resolve it explicitly before proceeding.
- Preserve established product patterns when they are intentional and fit the task. Do not redesign unrelated areas merely to impose a personal aesthetic.

## Required workflow

1. Inspect the product, task, existing implementation and available design references.
2. Read every applicable skill completely.
3. Extract mandatory requirements, prohibitions, conditional rules and completion criteria.
4. Plan the implementation around the actual user workflow.
5. Implement without abandoning the requirements midway.
6. Review the actual rendered interface at relevant screen sizes and states.
7. Audit the result against the original skill files and fix deviations.
8. Report limitations honestly. Never claim a check was performed if it was not.

## Core principle

Build software people can use, not a presentation about software. Use deliberate product-design judgment rather than assembling generic components.
