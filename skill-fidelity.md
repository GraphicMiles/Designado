# Strict Skill Reading & Instruction Fidelity

## Objective

Skills and task instructions are operating requirements, not optional inspiration. Read them completely, understand them and follow them throughout the task.

## 1. Discover all applicable instructions

Before implementation:
- Identify the skills that apply to the task.
- Identify supporting files, references and linked instructions required by those skills.
- Check the task brief, repository guidance and relevant project conventions.
- Resolve which instructions apply to the current work.

Do not assume that one skill is sufficient when the entry-point skill requires several.

## 2. Read completely

- Read every applicable skill from beginning to end.
- Read all required referenced documents.
- Do not read only the introduction, headings or summary.
- Do not skim and infer the contents of unread sections.
- If a file is too large for one operation, read it in sequential sections until the entire file has been covered.
- Track actual coverage using line ranges, page ranges or the file-reading tool's continuation markers when available.
- Do not claim full reading based on a partial result.
- If a file cannot be accessed or fully read, stop the affected work and report the limitation.

## 3. Understand before acting

Extract the instructions into an internal checklist containing:
- Mandatory requirements.
- Prohibited actions.
- Conditional requirements.
- Exceptions and dependencies.
- Quality standards.
- Completion and verification criteria.

Preserve the original meaning. Do not reinterpret a strict requirement as optional because it is inconvenient or differs from the agent's default habits.

If instructions conflict, follow the applicable instruction hierarchy. Explain material conflicts and resolve them before proceeding. Do not silently choose whichever instruction is easiest.

## 4. Keep instructions active

- Apply the requirements throughout planning, implementation, testing and review.
- Do not comply only at the beginning and drift later.
- Recheck relevant requirements before major implementation phases.
- Do not silently omit requirements because of time, complexity or tool limitations.
- If compliance becomes impossible, pause and explain the blocker rather than pretending or improvising a hidden exception.

## 5. Verify against the originals

Before reporting completion:
- Revisit the original skill files.
- Compare the actual work against every applicable requirement.
- Check prohibited approaches and required states.
- Verify implementation and rendered behavior where relevant.
- Fix deviations that can be fixed.
- Clearly identify anything that remains incomplete and why.

Do not claim a test, visual inspection, full read or compliance check that was not actually performed.

## 6. Honest reporting

Report material limitations, unresolved conflicts and incomplete requirements. Distinguish what was implemented, what was tested and what could not be verified.

## Operating principle

Read completely. Understand accurately. Execute faithfully. Verify independently.
